# پنل کنترل شیشه‌ای

> راهنمای طراحی و استفاده‌ی لایه‌ی UI/UX جدید Elegram.

---

## چرا پنل روی یک ربات همراه است؟

دکمه‌های شیشه‌ای (inline keyboard) در تلگرام **فقط برای ربات‌ها** ممکن‌اند.
یک اکانت کاربری وقتی `replyInlineMarkup` را به پیام وصل می‌کند، سرور حتی خطا هم
نمی‌دهد: مارک‌آپ را بی‌صدا حذف می‌کند. `callback_query` هم فقط به ربات‌ها تحویل
داده می‌شود. پس:

| کار | با چه هویتی |
| --- | --- |
| خواندن چت‌های محافظت‌شده، شکار رسانه‌ی محوشونده، آرشیو کردن، گذاشتن کامنت | اکانت خودت (MTProto) |
| کشیدن پنل، دکمه، صفحه‌بندی، تأیید دومرحله‌ای | ربات همراه (Bot API) |

ربات هیچ دسترسی‌ای به آرشیو تو ندارد و هیچ کاری را خودش انجام نمی‌دهد؛ فقط
«صفحه‌نمایش» است. اگر `BOT_TOKEN` را خالی بگذاری، تمام قابلیت‌های قبلی سر جایشان
هستند و فقط پنل وجود ندارد.

## راه‌اندازی در سه قدم

1. از [@BotFather](https://t.me/BotFather) یک ربات بساز و توکنش را بگیر.
2. در فایل محیطی: `BOT_TOKEN=123456:ABC-DEF…`
   (اگر می‌خواهی مالک پنل کسی جز اکانت لاگین‌شده باشد، `PANEL_OWNER=<user id>`)
3. سرویس را ری‌استارت کن، در اکانت خودت `.panel` را بفرست و لینک را باز کن.

فقط مالک جواب می‌گیرد؛ هر کس دیگری با یک پیام کوتاه رد می‌شود.

## نقشه‌ی صفحه‌ها

```
خانه (داشبورد)
├── 🔁 سیو خودکار ─┬─ صفحه‌بندی ─── جزئیات چت ─┬─ روشن/خاموش سیو خودکار
├── 🪞 آینه ───────┘                          ├─ روشن/خاموش آینه
│                                             └─ حذف از لیست‌ها (با تأیید)
├── 🗨️ کامنت اول ─┬─ صفحه‌بندی
│                 ├─ افزودن/ویرایش کانال (کانال در خط اول، متن در خط‌های بعد)
│                 └─ خاموش کردن یک کانال (با تأیید)
├── 📥 صف ───── پاک کردن صف (با تأیید)
├── 📈 آمار
├── 🧰 ابزارها ─┬─ ذخیره با لینک پست
│               ├─ افزودن چت به آینه
│               ├─ افزودن چت به سیو خودکار
│               └─ تنظیم کامنت اول
├── ⚙️ تنظیمات ─┬─ همزمانی آرشیو ‎−/+‎
│               ├─ ری‌اکشن پس از ذخیره (روشن/خاموش)
│               └─ چرخش سطح لاگ
└── 📖 راهنما
```

یک پیام، همه‌ی صفحه‌ها: پنل همان کارت را ویرایش می‌کند و کارت جدید نمی‌فرستد.
وقتی چیزی تایپ می‌کنی (مثلاً یک لینک)، پنل خودش را پایین‌تر جابه‌جا می‌کند تا
همیشه آخرین پیام چت باشد.

## سیستم طراحی

همه‌ی سطح‌ها — کارت‌هایی که اکانت در آرشیو می‌نویسد و صفحه‌های پنل — از یک
مجموعه‌ی مشترک ساخته می‌شوند: `src/ui/theme.js`.

```
src/ui/theme.js    خط‌ها، آیکون‌ها، ردیف کلید/مقدار، گیج، پیل، نقل‌قول
src/ui/cards.js    کارت‌های اکانت (متن خالص، بدون دکمه)
src/ui/glass.js    دکمه‌ها، صفحه‌بندی، کدگذاری مسیر در ۶۴ بایت
src/ui/panel.js    صفحه‌های پنل — توابع خالص: (view) => { text, keyboard }
```

### قواعد چیدمان

* یک نوار عنوان، همیشه با `header()`
* یک خط وضعیت زیر آن، اگر چیز زنده‌ای برای گفتن باشد
* بخش‌ها با ترتیب ثابت: این چیست ← چه می‌کند ← تو چه می‌توانی بکنی
* کیبورد آینه‌ی همان بخش‌ها است، از بالا به پایین، دو ستونه
* آخرین ردیف همیشه ناوبری است: بازگشت، بروزرسانی، بستن

### قواعد escape

* هر چیزی با نام `*Raw` و همچنین `hint()` و `header()` ورودی **HTML** می‌گیرد.
* بقیه ورودی **متن خالص** می‌گیرند و دقیقاً یک بار escape می‌کنند.
* `quote()` اول برش می‌زند، بعد escape می‌کند — برش روی `&amp;` نصفه، HTML را خراب می‌کند.
* فقط تگ‌هایی به‌کار می‌روند که هم MTProto و هم Bot API می‌فهمند:
  `b i u s code pre a`. یک تگ پشتیبانی‌نشده یعنی پیام رد شده، نه ظاهر بد.
* یک استثنای عمدی: **متن کامنت اول** بدون parse mode فرستاده می‌شود — متن کاربر
  باید بایت‌به‌بایت همان باشد که نوشته، نه چیزی که پارسر از آن می‌فهمد.

### کدگذاری مسیر دکمه‌ها

`callback_data` فقط ۶۴ بایت دارد و یک شناسه‌ی چت ۱۴ بایتش را می‌خورد. پس مسیرها
تک‌حرفی‌اند: `c:t:m:-1001234567890` یعنی «صفحه‌ی چت، اکشن toggle، سطل mirror،
این شناسه». `pack()` اگر از ۶۴ بایت رد شود، خطا می‌دهد — سکوت در این نقطه یعنی
دکمه‌ای که چت اشتباهی را عوض می‌کند.

## نکته‌های رفتاری

* **هیچ حذفی یک‌مرحله‌ای نیست.** حذف چت، خاموش کردن کامنت اول و پاک کردن صف، هر
  سه تأیید می‌خواهند.
* **خاموش کردن آینه، آرشیو را پاک نمی‌کند.** هر چه ثبت شده سر جایش می‌ماند. و
  خاموش کردن کامنت اول، کامنت‌های گذاشته‌شده را پاک نمی‌کند.
* **تغییرهای «زنده»** (همزمانی، ری‌اکشن، سطح لاگ) تا ری‌استارت بعدی می‌مانند؛
  برای همیشگی‌شدن باید در فایل محیطی نوشته شوند.
* **صف بک‌لاگ کلیک‌ها را اجرا نمی‌کند:** پنل هنگام بالا آمدن، آپدیت‌های
  انبارشده را تأیید و رد می‌کند تا یک تپ قدیمی روی وضعیت جدید اجرا نشود.
* **پنل هیچ‌وقت آرشیو را زمین نمی‌زند:** توکن غلط یا رد‌شده فقط یک هشدار در لاگ
  است و سرویس بدون پنل ادامه می‌دهد.
